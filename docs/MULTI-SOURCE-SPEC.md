# 多源转存（一个任务多个分享链接）开发文本

> 版本：v1（2026-11-23）
> 前置口径：一个任务只属于一个网盘。建光鸭任务就只有光鸭的链接，不存在跨盘混用。

---

## 一、需求原话归纳

1. 一个任务可以带**多个分享链接**，最多 **5 个**。
2. 链接区从单框变成一个可增删的列表。
3. **第一行是默认链接**，右端是 **「+」**，点一次在**末尾**追加一行空框；第一行始终保留「+」。
4. **第 2～5 行是附加源**，右端是 **「−」**，点一下删除这一行（包括里面的内容）。
5. 源多，但**规则只有一套**：保存位置、季度、命名规则、tmdb id 开关、更新日、播出时刻全任务共用一份，不随源变化。
6. **不跨网盘**：所有源都是同一个网盘的链接，网盘由任务的保存位置决定。

一张图说清：

```
任务（光鸭）
├─ 保存位置 / 季度 / 命名规则 / 更新日 / 播出时刻   ← 全任务唯一一份
└─ 链接
   ├─ 第1行（默认，必填）              [+]
   ├─ 第2行（附加源）                  [−]
   ├─ 第3行（附加源）                  [−]
   └─ …最多第5行                      [−]
```

## 二、UI 设计

### 2.1 链接区结构

| 位置 | 右端控件 | 行为 |
|---|---|---|
| 第 1 行 | `+` | 末尾追加一行空框；已满 5 行时置灰不可点 |
| 第 2~5 行 | `−` | 立即删除该行及其内容，后行上移 |

- 每行一个单行输入框（与现有「分享链接」框同规格，高 56dp，单行、长链接只显示前段）。
- 行间距 8dp；区块标题仍为「分享链接」，不新增小字说明。
- 行内不再出现网盘标签：任务本身已经确定是哪个盘，`+` 出来的框默认沿用同一网盘。
- 第 2 行起在行首加一个序号小字「源2 / 源3」，避免用户分不清哪行是附加的。

### 2.2 校验与提示

| 场景 | 表现 |
|---|---|
| 第 1 行空 | 保存时红字「请粘贴分享链接」，与现有一致 |
| 附加行空 | 视为未填写，保存时自动丢弃，不报错 |
| 链接无法解析 | **该行下方就地红字**「链接无法识别」，不等点保存 |
| 链接域名不属于本任务网盘 | 该行下方红字「该任务是光鸭任务，请粘贴光鸭链接」 |
| 与前面某行重复 | 该行下方红字「与第 N 行相同」，禁止保存 |
| 已达 5 行 | 第 1 行 `+` 置灰（保留位置，不隐藏，避免布局跳动） |

### 2.3 其他页面

- **卡片**：底部元信息在源数 > 1 时追加「· 2 源」（如「周一、周二 · 光鸭 · 自动 · 2 源」）。
- **运行日志**：一次运行里有多个源时按源分行，写清「源1 成功 3 集 / 源2 失败：xxx」。
- **编辑任务**：把多行原样带回；删除行后保存即生效。

### 2.4 明确的「不做」

- 不做粘贴自动拆行（一次贴一个链接，靠 `+` 追加）。
- 不做跨网盘混用。
- 不做每源独立规则（没有「主源」角标，没有按源设置命名/季度）。
- 不做源内清晰度选择、不做源优先级手动排序（顺序固定为行序）。

## 三、数据模型

### 3.1 新表 `task_sources`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | Long PK auto | 主键 |
| taskId | Long | 关联 `tasks.id`，加索引 |
| position | Int | 0 = 第 1 行（默认），1..4 = 附加源 |
| shareUrl | String | 原始分享链接 |
| shareId | String | 解析出的分享 id |
| passcode | String | 提取码（可空） |
| createdAt | Long | 建行时间，仅排查用 |

> 不存 `driveType`：网盘由任务统一决定（`tasks.driveType`），从根上杜绝跨盘。

### 3.2 `tasks` 旧字段处理

`shareUrl / shareId / passcode` 保留但标记为**历史字段**：

- 读取一律走 `task_sources`；
- 写入时同步把第 1 行写回这三个字段，保证任何漏改的地方仍能读到正确的主链接，也方便回滚。

### 3.3 迁移（DB 7 → 8）

1. `CREATE TABLE task_sources (...)` + 索引 `index_task_sources_taskId`。
2. 对每条已有任务插入一行 `position = 0`，值取 `tasks.shareUrl / shareId / passcode`。
3. 只加表，不动 `tasks` 结构，迁移可重复执行不报错（`INSERT OR REPLACE` 语义按主键）。

**回滚策略**：任务表结构没变，引擎开关切回「只读第 1 行」即可回到旧行为。

## 四、引擎逻辑

### 4.1 数据流（一轮运行）

```
读取任务 → 读出 N 个源（position 升序）
        → 对每个源：取分享目录树 → 按目标文件名解析集号 → 得到该源集号集合
        → 合并集号集合（去重）→ 得到「盘里已有集」= 集合大小
        → 与 TMDB 最新集 / 总集数比较 → 三态标识
        → 逐源转存：目标集号已在集合里 → 跳过；否则转存并加入集合
```

### 4.2 关键规则

- **同集去重**：按行序，靠前的源优先。第 1 源已经有的集，第 2 源同集号不再转存。
- **失败隔离**：某一源取树失败 / 掉登录 → 记「源K 失败：原因」，继续跑下一个源；整轮只要至少一个源成功就记为成功，全部失败才整体失败。
- **串行不改**：仍在现有 `runLock` 内跑完所有源，不新增并发，避免触发网盘风控。
- **集数口径不变**：「盘里有多少集」= 合并后去重集号的数量；「转存完」仍是集号数量 ≥ 总集数。
- **保存位置不变**：所有源转存到任务同一个保存目录，不按源分目录。

### 4.3 日志

每轮多源时输出：

```
源1(光鸭) 段：扫描 48 集，新增 3
源2(光鸭) 段：扫描 12 集，全部已存在，跳过 12
合并：48 集 / TMDB 最新 48 / 共 48 → 转存完
```

## 五、开发步骤

> 每步独立可编译、可回退；每步结束做一次本地 git 提交 + 追加中文 `CHANGELOG.md`。改代码前先确认本文件。

### Step 1 — 数据层（0.5 天）

1. 新建 `data/db/TaskSourceEntity.kt`。
2. `AppDatabase` 版本 7→8，新增 `MIGRATION_7_8`（建表 + 索引 + 老数据搬入）。
3. `TaskSourceDao`：`listByTask`、`replaceAll(taskId, list)`、`deleteByTask`。
4. `TaskRepository` 增加 `sourcesOf(taskId)`、`saveSources(taskId, sources)`；`createTask / saveEdit` 写第 1 行时同步旧字段。
5. 单测：迁移后老任务有 1 行、`replaceAll` 顺序正确、5 行上限的错误被拒。

**验收**：装包后老任务照常检测转存，行为与改前完全一致（多源还没接）。

### Step 2 — 表单 UI（0.5 天）

1. `NewTaskScreen` 链接区改成 `LinkRow` 列表：
   - 第 1 行 `+`，第 2~5 行 `−`；
   - 行首小字「源2 / 源3」；
   - 行内校验（无法识别 / 网盘不符 / 重复）就地红字。
2. 状态用 `mutableStateListOf<LinkField>`（每行带稳定 key），删行不串内容。
3. 保存时丢弃空行、校验至少 1 行有效；成功后表单回到 1 行。
4. 编辑任务时按 `sources` 回填。

**验收**：能加/删到 5 行并保存；重启后多行原样回来；老单源任务打开只有 1 行。

### Step 3 — 引擎多源（1 天）

1. `TaskRunner.run` 读出全部源，按 position 升序遍历。
2. 扫描阶段：每源各自解析集号，合并到 `MutableSet<Int>`。
3. 转存阶段：逐源转存，命中集合则跳过；单源异常捕获后记日志继续。
4. `resolveTmdb` / `SnapshotCalc` 入参不变，只喂合并后的数字。
5. 日志按源分行（见 4.3）。

**验收**：造两个源（第 2 源含第 1 源没有的集）→ 检测显示合并集数；重复集不重复转存；把第 2 源链接改坏 → 只报源2 失败，任务状态仍按源1 计算。

### Step 4 — 展示与回归（0.5 天）

1. 卡片元信息加「· N 源」。
2. 运行日志按源分行展示。
3. 真机回归清单：新增多源 / 编辑删源 / 5 行上限 / 重复链接拦截 / 单源老任务 / 卡片与日志显示。

## 七、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 多源让单轮耗时变长（5 源最难） | 整轮可能数分钟 | 日志逐源打点，卡片显示「源2/3」进度；不做并发 |
| 迁移写错导致任务读不到链接 | 任务全部报「链接无效」 | 迁移只加表不改列；旧字段持续写回，可回滚 |
| 某源解析集号规则与主源不同（文件名格式不一） | 合并集数偏低 | 沿用现有「按目标文件名解析」逻辑，解析失败的行记日志并在卡片提示 |
| 用户以为多源能跨盘 | 粘了别的盘链接 | 行内即时校验，红字明确说明 |
