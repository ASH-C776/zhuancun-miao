# 转存过滤与去重方案（草案 v1，2026-11-24）

## 一、先把「缺 N 集」的口径说清

卡片上的三个数来自快照（`SnapshotCalc`）：

- 左边 `E201` = 目标目录里**最大的集号**（`localLastEpisode`）
- 右边 `E201（共211）` = TMDB **最新已播集**与**全季总集数**
- `缺 N 集` = `目标集数 - 盘里去重后的集号数量`，目标优先取「最新已播集」

而「盘里集号数量」= 目标目录（含直接子目录）里**能解析出集号的视频文件名**，按集号去重后的个数。

所以凡人修仙传 `E201 / 共211 / 缺87` 的真实含义是：**盘里只有 124 个不同的集号，但最大号已经到 201**。数字本身算得没错，错的是统计对象：盘里混进了不属于这一季的东西，中间也大量断号。

仙逆 `E265 / E168 / 共200 / 缺53` 同理：147 个不同集号、最大 265（已超过 TMDB 的 200 集）→ 典型的**跨季连续编号**（第 2 季从 201 接着编）被当成本季集号。

## 二、问题类型盘点（5 类）

| 类型 | 现象 | 现在怎么处理 | 后果 |
| --- | --- | --- | --- |
| A. 同层多个版本 | 同一集有 `EP01.mp4` 与 `EP01 重置版 V2.mp4`，或同名目录两套 | 两个都转存、两个都改名 | 目录里重复文件；虽说集号去重不计双份，但占空间、播放器重复 |
| B. 命名未命中 | 文件名解析不出集号（`第1话合集.mp4`、`01.mkv` 缺剧名等） | 照常转存，改名失败保留原名 | 目录里混入没改名文件；不参与集数统计 → 缺口虚高 |
| C. 剧场版/特别篇 | `剧场版.mp4`、`SP01`、`OVA`、`特别篇` 混在剧集目录 | 当普通视频转存 | 被算成「1 集」，或直接跳过不提示 |
| D. 跨季连续编号 | 第 2 季 `E201…E265`，TMDB 每季从 1 编号 | 按绝对集号统计 | 最大集号 > 总集数，缺口数错乱（就是仙逆那张卡） |
| E. 多源重复 | 3 个源都有同一集 | 依赖目标目录 diff，已有就跳过 | 正常（不需要额外改），但「源里有、盘里没有」的判断顺序要先定 |

## 三、应对方案

### 1. 新增一层「候选分类器」（纯函数，可单测）

对分享目录树里的每个视频文件，解析成四类之一：

- `MAIN`（正片）：能解析出「季 + 集号」，且不在剧场版/花絮关键词表里
- `SPECIAL`（特典）：文件名或所在目录命中 `剧场版 / 劇場版 / 特别篇 / SP / OVA / OAD / 特典 / 番外 / 合集 / 预告 / 花絮`
- `UNMATCHED`（未命中）：解析不出集号，也不是特典
- `NOISE`（噪声）：sample / trailer 等，沿用现有 `VideoTypes.isNoise`

转存策略：**只转 `MAIN`**。`SPECIAL` / `UNMATCHED` / `NOISE` 一律不转存、不写入目标目录，各自计数并在日志与卡片提示（例如「跳过 12 个非正片」），避免用户以为漏转。

### 2. 同集去重（同一 (季, 集号) 只留一个）

在一轮扫描里按 `(season, episode)` 建索引：

- 同一集出现多个候选 → 只取一个，其余计入「重复版本 N 个」
- 取舍优先级（建议，可按你的口径调整）：
  1. 文件名带 `重置 / 修正 / V2 / 修复` 的优先（通常画质修过）
  2. 其次比文件体积（大者优先）
  3. 再其次文件名更短、更「干净」
- 同名目录两套（如 `剧名` 与 `剧名 重置版 V2/`）→ 视为两个候选根，取**集数更多**的那一棵，另一棵整棵跳过

### 3. 跨源去重（已有机制，明确顺序即可）

任务是串行按源执行：源 1 成功写入后，源 2 靠目标目录 diff 判定「已存在」自然跳过。要补的只有一条：**源内先做完第 2 步去重，再 diff**，否则同一源的两个版本会同时被判定为「不存在」。

### 4. 季号归一（解决 E265 vs 共200）

不猜、不硬映射，分两步：

- 统计时只把 `1..tmdbTotal` 范围内的集号算进「已覆盖集数」；超出范围的记为「编号越界 N 个」，卡片上单独提示
- 若任务的季目录明确（如 `Season 2/`），则在该目录内按「本地编号 - 该季起始偏移」归一；偏移只在能确定时使用（同目录最小集号与 TMDB 该季集数能对上）
- 无法确定时**保持原样并提示**，绝不擅自改名或重新编号（改名不可逆，宁可提示也不猜）

### 5. 计数与卡片口径

- 「已覆盖集数」= `MAIN` 文件按 `(季,集号)` 去重后、落在本季范围内的个数
- 「缺口」= 目标集数 - 已覆盖集数（只在范围有效时给）
- 卡片补一行小字：`另有 12 个非正片 / 3 个重复版本 / 5 个编号越界`，只在该项不为 0 时出现
- 进度条分母用 TMDB 总集数，分子用已覆盖集数；不再出现「最大集号 > 总集数」的荒唐对照

### 6. 存量修复（关键，否则老任务还是怪数字）

- 下一轮运行时用新口径重算快照，卡片数字自动回正
- 已在盘里的「未命中 / 剧场版 / 重复版本」文件**不自动删除**（用户数据不可逆操作），只在卡片与日志提示「疑似非正片 12 个」，需要清理时由用户自己动手（后续可做「一键清理疑似非正片」按钮）

### 7. 开关与灰度

- 过滤策略挂在任务级开关 `只转正片（推荐开）`，新任务默认开、老任务默认保持旧行为，用户可在编辑页打开
- 关闭时退回现有行为（全部转存），出问题可立即回退，不用回滚版本

## 四、改动范围（预估）

- 新增 `transfer/EpisodeClassifier.kt`（纯函数 + 单测，约 12-18 例）
- `TreeSyncEngine` 选文件处插入「分类 + 同集去重」，是最核心的一处改动，需谨慎
- `SnapshotCalc` 增加「范围内覆盖集数」入参，`EpisodeCounter` 增加「越界/非正片」计数
- 卡片与日志增加提示行（`TaskListScreen` / `RunLogScreen`）
- 数据库：任务表加一个布尔开关（需迁移 v12），或先放任务级 SharedPreferences 规避迁移

## 五、待你拍板的 3 点

1. 同集多版本取舍：**重置/修正优先**（我建议）还是**原版优先**？
2. 未命中/剧场版：默认**不转存**（我建议），是否还要在日志里逐条列出文件名？
3. 跨季连续编号：先只提示不处理（我建议），还是要我尝试自动归一？

# 转存过滤与去重方案 v2（2026-11-24，按用户口径重写）

## 一、先回答「跨季」的疑问

你说得对：**指定季（1..99 或 0）的任务，统计本来就只看 `剧名/Season N/` 这一层**，不存在跨季混淆。出现 `E265 / 共200` 的是**多季（-1）或平铺（-2）**任务：统计函数从「剧名」根目录一路递归 3 层，把 `Season 1..N` 的文件名全倒进**同一个集号集合**，于是 S2 的 E65 被当成 E65、S1 的 E200 与 S2 的 E265 混排——不是真的跨季，是**统计方法把多季混在一起算**。

修复口径（按选择方式分开算，不再混）：

| 任务季设置 | 统计范围 | 卡片数字 |
| --- | --- | --- |
| `0` 特别版 | 仅 `剧名/Season 0/` | 与 TMDB Season 0 总数比 |
| `1..99` 指定季 | 仅 `剧名/Season N/` | 与 TMDB 该季总数比（现状就对，保持） |
| `-1` 多季 | **按季分区**统计，不合并 | 分区显示：`S1 12/12 · S2 5/13`，不再给一个混合的「缺 N 集」 |
| `-2` 平铺 | 剧名根目录这一层（不含季子目录） | 单季口径；若发现根目录混多季，提示「建议改选多季」 |

## 二、核心原则：**能命中、能改名，才转存**

用户口径原话：转存了多少个，这些就都应该是改过名的。因此把流程从「先转存、再尝试改名」改成**「先算目标名，再转存」**：

1. 扫描分享树 → 对每个视频算「目标文件名 + 目标季目录」
2. 算不出来（解析不出集号 / 规则不适用 / 文件名为空）→ **不转存**，计入「未命中 N 个」
3. 能算出来 → 才进入转存队列
4. 转存成功后立刻改名；**改名失败则删除这一轮刚复制过去的文件**（只删本轮自己创建的，不碰历史文件），并计入失败
5. 最终校验：本轮 `restoredFiles == renamedItems + 已存在跳过`，两者对不上就是 bug，要报出来

这样目录里永远只有「已命中且已改名」的文件，卡片数字也不会再被垃圾文件污染。

## 三、分类规则（每轮扫描先归类）

| 类别 | 判定 | 处理 |
| --- | --- | --- |
| `MAIN` 正片 | 能解析出集号，且不在特典关键词表内 | 转存 + 改名 |
| `SPECIAL` 特别篇 | 文件名/目录含 `特别篇 / SP / OVA / OAD / 特典 / 番外 / 花絮短片`，且**能解析出集号** | 作为 **Season 0 正片**转存到 `剧名/Season 0/`，命名 `剧名 S00E01` |
| `MOVIE` 剧场版 | 含 `剧场版 / 劇場版 / 剧场 / Movie / 电影版` | **不转存**（独立作品，不参与集数） |
| `UNMATCHED` 未命中 | 解析不出集号（`合集.mp4`、`01.mkv` 无剧名等） | **不转存**，计数并提示 |
| `NOISE` 噪声 | sample / trailer / 预告等（沿用现有 `VideoTypes.isNoise`） | 不转存，不提示 |

要点：**特别篇必须有集号才算 SPECIAL**。只有 `剧场版.mp4` 这种没有编号的，归 MOVIE 不转；`SP01.mp4`、`特别篇 第3话.mp4` 有编号的，进 Season 0。

## 四、同集去重（同一目标路径只留一个）

- 按「目标季目录 + 目标文件名」建索引，而不是按源文件名
- 同一目标路径出现多个候选 → 只转一个，其余计「重复版本 N 个」
- 取舍优先级：`重置/修正/V2/修复` → 体积更大 → 文件名更短
- 同名目录两套（`剧名` 与 `剧名 重置版 V2/`）→ 取集数更多的整棵，另一棵跳过

## 五、多源

保持串行：源 1 写完，源 2 靠目标目录 diff 跳过。新增顺序约束：**源内先完成分类与同集去重，再与盘里 diff**。

## 六、计数与卡片

- 已覆盖集数 = 该任务季范围内、`MAIN`/`SPECIAL` 去重后落在 `1..总集数` 的个数
- 缺口 = 目标集数 - 已覆盖集数
- 卡片小字提示（不为 0 才显示）：`另有 12 个未命中 / 3 个重复版本 / 2 个剧场版`
- 平铺任务若检测到根目录里出现「同一集号的两套命名」或「季目录痕迹」，提示改选多季

## 七、存量与灰度

- 下一轮按新口径重算快照，老任务数字自动回正
- 盘里已有的未命中/剧场版文件不自动删，只提示（后续可加「清理疑似非正片」）
- 任务级开关 `只转命中项`（新任务默认开，老任务默认沿用旧行为），出问题一键回退

## 八、改动与推进

1. `transfer/EpisodeClassifier.kt` 纯函数 + 单测（分类、目标名可算性、同集去重、S0 归属）
2. `TreeSyncEngine` 接入：先分类 → 先算名 → 只转命中 → 改名失败回滚删除
3. `TaskRunner.countLocal` 改为**按季分区统计**（多季/平铺任务的关键修复）
4. `SnapshotCalc` 支持分区结果；多季卡片文案改 `S1 x/y · S2 a/b`
5. 卡片与日志提示三类跳过计数
6. 存量重算 + 真机回归（多季任务、特别版任务、含剧场版与重复版本的分享各一例）

## 九、剩下要你确认的两点

1. **指定季（如第 2 季）的任务里同时出现特别篇**：是「只转该季、特别篇不转」，还是「特别篇顺手进 Season 0」？（我建议前者：范围明确就不越界）
2. **多季任务卡片怎么显示**：`S1 12/12 · S2 5/13`（我建议），还是只显示当前最新季的缺口？
